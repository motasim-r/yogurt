# Yogurt Soul

## North Star

**Yogurt is the AI-native work app built on living company context, where meetings, chats, docs, email, and decisions become one system that helps people think, coordinate, and get work done.**

Yogurt is not a better meeting notes app. It starts from Granola's wedge, but its destination is the work app: the place you open in the morning because your work already lives there.

## Why Yogurt Exists

Work is fragmented across too many surfaces:

- meetings hold decisions
- chat holds follow-up and debate
- docs hold drafts and plans
- email holds external context and commitments
- tasks and boards hold execution state

When that context is scattered, AI is weak, workflows are brittle, and people keep re-explaining the same thing across tools.

Yogurt exists to make that context one system. The point is not just to store more information. The point is to make context usable:

- searchable
- connected
- cited
- actionable
- shared

The product bet is simple: if Yogurt has the right context, AI can do far more than summarize. It can help decide, draft, coordinate, prep, remind, and start work.

## Why Now

Several forces now make this product possible:

1. Granola has already proved that meeting-first context is a powerful wedge. It captures a high-signal stream of company truth without the social cost of visible meeting bots.
2. Users already want more than notes: cross-meeting chat, one-click workflows, deeper integrations, proactive follow-ups, and team memory.
3. Lark proved that a unified work surface can beat fragmented tools when everything important happens in one place.
4. Sentra and Micro validate the direction from adjacent angles: organizational memory, centralized work context, and one place for the core surfaces of work.
5. AI is finally good enough to reason across messy context, but only if that context is available, connected, and trustworthy.

## Why Granola Is The Right Wedge, But Not The Final Form

Granola matters because it already owns the best wedge in the category:

- meeting capture
- enhanced notes
- cross-meeting chat
- team folders / shared context
- privacy-first, bot-free product instincts

But Yogurt should not think of Granola as the endpoint. Granola is the starting layer. The final form is broader:

- meetings are one input, not the whole product
- notes are one artifact, not the whole workflow
- chat should not only answer questions; it should start work
- docs should not be disconnected from the conversations that created them
- external context should not live outside the system by default

The ambition is not "Granola plus more tabs." The ambition is a context-native work system.

## Core Belief

Most important company truth lives in interactions.

That includes:

- meetings
- chats
- email
- quick notes and monologues
- attached files and exports that explain a decision

The job of Yogurt is to turn that interaction stream into usable memory and action.

This implies a few product truths:

- Unstructured context is primary.
- Structured objects are downstream conveniences.
- Provenance matters. The system should know where conclusions came from.
- AI should act on top of shared context, not on isolated prompts.

## Product Pillars

### 1. Context First

Yogurt should centralize the context behind work, not just the output of work.

### 2. One Work Surface

The right long-term UX is not endless app switching. It is one work app where the important surfaces of work live together.

### 3. AI That Acts, Not Just Answers

Useful AI does more than summarize and chat. It should prepare, synthesize, draft, route, remind, and kick off work while keeping the user in control.

### 4. Human In Control

Yogurt should feel like a conductor's console, not an autonomous black box. The user stays the boss.

### 5. Citations By Default

Claims, summaries, drafts, and actions should be traceable back to the interactions and sources that produced them.

### 6. Privacy And Local-First When Possible

Granola's bot-free, local-capture instincts are an advantage and should remain part of the product DNA.

### 7. Unstructured First, Structured When Useful

Yogurt should not force users to pre-structure work before they can get value. It should absorb messy context first, then help structure it where useful.

## Target Product Shape

Yogurt should grow toward a single work system that includes:

- meetings
- chat
- docs and wiki
- tasks and project coordination
- email and external context import
- workflow and agent layer

This does not mean every primitive must be rebuilt on day one. It means the product should be designed as one connected system rather than isolated features.

## What Yogurt Is Not

Yogurt is not:

- a generic enterprise suite built from the top down
- a pure Slack clone
- a pure Notion clone
- a pure meeting notes app
- a task copilot forever
- a feature checklist copied from Lark without the context-layer thesis underneath it

## Non-Goals For Now

These are explicit non-goals for the current phase:

- out-Slacking Slack on every communication primitive
- rebuilding every enterprise back-office workflow before the context foundation is strong
- pretending the current desktop build already is the full super app
- optimizing first for generic enterprise procurement instead of core user leverage

## Decision Filters

Every major product, UX, and architecture decision should be tested against these questions:

1. Does this centralize context?
2. Does this reduce tool-switching?
3. Does this make AI more context-rich or more actionable?
4. Does this preserve citations, control, and trust?
5. Does this move Yogurt toward being the place work happens?

If the answer is no to most of these, the work is probably off-direction.

## Product Language

Preferred framing:

- work app
- living company context
- organizational memory
- meeting-first knowledge layer
- AI-native workspace
- the place work gets done

Avoid as primary framing:

- meeting notes tool
- just a task copilot
- another Slack / Notion clone
- copied Lark features

The point is not cosmetic language. The language should remind contributors what category Yogurt is actually trying to create.

## Naming Contract

- Yogurt is the product identity inside this repo.
- Granola is the inspiration, wedge, ecosystem, and pitch target.
- It is fine to describe Yogurt as a product direction Granola could grow into.
- The repo should still make sense even if a reader has never used Granola.

## What This Means For The Current Repo

Today, the repo is an early desktop slice of the larger product. That slice currently centers on:

- Granola context sync
- home feed and note access
- cross-meeting AI chat
- docs workspace
- task extraction and task execution workflows

That is narrower than the final vision, but it is on the right path. The correct discipline is:

- be ambitious in doctrine
- be honest in capability docs
- design new work so it compounds toward the larger system
